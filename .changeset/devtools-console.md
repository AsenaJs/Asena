'@asenajs/asena': minor
---

Core works with `asena console`, the development console of `@asenajs/asena-cli`, which runs the app as a child process and talks to an agent inside it over IPC.

- **Applications:** nothing to import or configure. In a process `asena console` started, the agent attaches once the server is ready. It reports the app's components and their dependencies, routes, pages, websockets, schedules, event and message handlers, exception handlers and `@Config`, sends memory, CPU, event-loop lag and readiness every second, and runs a schedule, emits an event or sends a message through the app's own dispatch path on request. It records every `@On`, `@MessagePattern` / `@EventPattern` and `@Schedule` dispatch, and every HTTP request when the adapter supports it, with the steps that handled it (middlewares, validator, controller, `@Catch`, `@Config.onError`, `@NotFound`) and what the app wrote through `console.*` and `process.stdout` / `process.stderr` while it was in scope, capped at 100 entries or 16 KiB. In a process with an IPC channel, loading `@asenajs/asena/devtools` wraps those output functions once and keeps them wrapped for the life of the process; outside a record the wrappers only pass the call on, and every write still reaches its stream. A console method the app replaced before that load is left as it is, and a line printed through it is in the record only if the replacement writes to `process.stdout` / `process.stderr`: wrapping the replacement would record the arguments before the app's own redaction, and Bun's console does not write through those streams. A console method the app replaces after that load is recorded as the replacement prints it.
- **Without the console, nothing changes.** Core starts the agent only when the console's hook, `globalThis[Symbol.for('asena.devtools')]`, is a function and the process has an IPC channel (`process.send`). Otherwise no agent runs, no request is recorded and no handler or output function is wrapped. Under `NODE_ENV=production` core does not start the agent or record anything, even in a process `asena console` started, and logs a warning saying so.
- **`@asenajs/asena/devtools`:** the new entry point the console loads. It exports `attachDevtoolsAgent`, the hook key `DEVTOOLS_HOOK`, `buildDevtoolsSnapshot` and the typed IPC protocol between the agent and the console.
- **Adapter authors:** `AsenaAdapter` (from `@asenajs/asena/adapter`) gains an optional `attachDevtools?(bus)`. In a console process core calls it once with the server's devtools bus, right after the adapter is resolved and before any `use()`, `registerRoute()`, `onError()`, `onNotFound()`, `registerWebsocketRoute()` or `start()` call. The adapter opens a record for each HTTP request, runs the request inside it and closes it with the response status; core adds its own steps to that record, and the adapter adds only the steps that run outside them, such as its own 404 or error response. The bus is not exported: an adapter declares the members it uses (`enabled`, `open`, `run`, `step`, `close`) as a local interface. Adapters without the method work unchanged, and an adapter whose method is never called keeps its request path as it is.
- **`RouteParams.validatorName`:** a new optional field with the component name of the route's `@Middleware({ validator: true })` validator, set on every route that has one, so an adapter can name the validator step.
